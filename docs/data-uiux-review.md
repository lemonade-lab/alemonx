# 数据工作区 UI/UX 复盘

本文保留初次复盘的设计依据；Connect 后续已接入多种 SQL 引擎，当前实现与未完成项以 [Connect 升级进度](connect-upgrade.md) 为准。

## 定位与边界

建议定位为「面向机器人开发者的轻量数据工作区」，而不是当前就宣称完整替代 Navicat。
目前 Connect 只有 SQLite 文件连接；MySQL、PostgreSQL、事务会话、导入导出、关系设计等能力尚未实现。
这是代码审查与社区工具交互模式对照后的产品建议，不是用户访谈或可用性实验结论。

保留统一侧边栏的 Redis / SQLite / Connect 三个入口：前两个是开箱即用的工作区能力，最后一个是用户管理数据库连接的客户端。
这三项并非同一分类维度，需要通过副标题解释，而不要让使用者猜测 SQLite 和 Connect 为什么重复。

| 入口 | 核心任务 | 不应混入 |
| --- | --- | --- |
| Redis | 浏览键值、维护本地 Redis 服务；现有自定义 Redis 连接继续可用 | 远程连接的服务启停 |
| SQLite | 直接使用工作区默认数据库 | 手工填写默认库路径、系统运维库写入 |
| Connect | 新建、测试、命名和管理用户数据库连接 | 把默认库当作需要手工创建的连接 |

## 本次完成

- Redis 服务管理组件从设置模块迁到数据模块，删除设置页的重复入口，不修改服务接口、已有配置或磁盘数据。
- Redis 工作区分为「数据浏览 / 本地服务」；本地服务不依赖连接目录请求成功，服务故障时仍有修复入口。
- 两个 Redis 视图之间切换保留键值草稿；离开 Redis 或关闭窗口清理临时数据与凭据。
- 服务配置修改后使连接目录缓存失效，更新默认地址展示。
- 保留外部服务不可启停/改配置的保护，保留写入确认及已有权限边界。

## 建议优先级（以下尚未实现）

后续实施更新：已完成连接上下文条、Redis 显式测试和连接配置收起、命令编辑器默认收起、Connect 命名保存/选择/测试/断开、新建连接和旧路径兼容、SQLite 表搜索。Redis 已完成键空间浏览、新建键、TTL/重命名/删除、字符串 CAS 保存，以及 Hash、列表、集合和有序集合的可视化编辑；Stream 仍为只读预览。以下列表保留完整设计方向；其他项仍为后续建议。当前 Connect 仅支持 SQLite，尚未增加驱动选择器或其他引擎。

### P0：明确操作对象，降低误操作

- 顶部统一上下文条：连接名、引擎、服务器地址或服务器文件路径、数据库编号、连接状态和只读状态；不能只靠颜色表达。
- 自定义 Redis 连接使用显式「连接 / 测试连接」，不要让「扫描键」兼任连接动作。服务状态与远程连接状态分开。
- 新手默认使用本地连接；地址、用户名和密码放入可展开的连接配置，避免首屏被表单占满。
- 统一使用已有确认弹窗，明确目标连接、对象及影响；停止服务与删除数据分开。将来支持事务前，不展示会误导用户的「撤销」。
- 离开有草稿的编辑区之前提示；不得为了保存草稿将密码、SQL 或数据库内容写入浏览器持久化。

### P1：从表单集合变成数据工作区

- 共用布局：外侧功能导航，内部对象列表与右侧编辑器；窄屏对象列表可收起，不再叠加固定宽度侧栏。
- Redis 键列表支持搜索、类型与 TTL 展示；按类型提供 Hash/Set/List/ZSet 可视化编辑，命令编辑器作为高级工具，而不是新增数据的唯一入口。元数据按页读取，避免每个键产生无界请求。
- SQLite / Connect 分开「数据、结构、查询」视图，共用 SQL 编辑器和结果表格；提供表搜索与明确空库引导。
- Connect 提供「新建连接 → 选择已支持的引擎 → 填写参数 → 测试 → 命名保存」，连接列表支持重命名、断开和忘记。未实现的引擎不作为可用选项。
- 连接删除必须说明「只忘记连接，不删除数据库」。历史路径迁为 SQLite 连接时保留原记录和回退能力。

### P2：围绕开源维护成本扩展

- 先抽象驱动能力描述（事务、分页、只读、结构编辑），按能力显示操作，避免为每个数据库复制整套界面。
- 再逐步加入 MySQL/PostgreSQL、带范围提示的导出、显式保存的查询文件。新增驱动时评估许可证、依赖体积和平台支持。
- 区分「查看 / 编辑数据 / 管理连接 / 管理本地服务」权限；当前超级管理员限制保留，权限后端实现前不能仅放开前端按钮。
- 增补暗色、窄屏、键盘、读屏、错误恢复测试。性能验收覆盖大键空间、大表、慢查询和取消状态。
- 不静默保存凭据；如将来允许保存，先设计服务端密钥存储与权限模型。

## 社区参照
