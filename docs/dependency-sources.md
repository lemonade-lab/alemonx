# 系统依赖源管理

ALemonX 把依赖源当作系统配置事务，而不是下载加速开关。当前 MVP 全平台只读：可以检查镜像元数据、审计备份和清理 ALemonX 遗留文件，但不会自动追加、切换或恢复系统仓库。

## DNF/YUM：不再追加 BaseOS/AppStream

CentOS Stream 的 BaseOS 和 AppStream 是同一套系统包集合。把一个镜像以新的仓库 ID（例如 `alemonx-baseos`）追加并启用，会让 DNF 同时使用系统原仓库和镜像仓库来求解依赖；两者元数据并非完全同步时，可能出现同一软件包的不同构建互相冲突，例如 Cockpit 组件。

因此，DNF/YUM 当前只提供只读元数据预检，并隔离旧版追加仓库模式。若系统已有 `/etc/yum.repos.d/alemonx-mirror.repo`，界面会在确认后备份并删除该带有 ALemonX 所有权标记的文件；不会修改任何发行版自带的仓库文件。同名但不带标记的文件会被拒绝删除。不要用 `--allowerasing`、`--nobest` 或 `--skip-broken` 掩盖由该旧模式产生的冲突。

后续若重新开放 DNF/YUM 写入，必须采用完整替换事务：只识别并修改确认为 CentOS Stream 官方仓库的现有条目，保留原仓库 ID、`gpgkey`、`enabled`、模块及第三方仓库；逐文件原样备份，索引刷新失败即还原。无法精确识别的系统保持只读。

## APT 与其他平台

APT 旧版 drop-in 与其他平台的自动写入入口均已停用。若存在带 ALemonX 所有权标记的固定遗留文件，用户可以确认后将其备份并移除；备份仅供审计，MVP 不提供恢复写入，以免重新启用不兼容仓库。

## 运维建议

- 在公开网络暴露工作台前开启认证并限制管理端访问。
- 镜像预检只表示元数据可访问，不表示该镜像已被系统采用。
- 出现依赖冲突时，优先移除 ALemonX 遗留管理文件，再分析已有第三方仓库和发行版仓库状态。
